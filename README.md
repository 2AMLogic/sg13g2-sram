# sg13g2-sram

An SRAM macro on [IHP SG13G2](https://github.com/IHP-GmbH/IHP-Open-PDK), a
130 nm SiGe BiCMOS open PDK — built and verified by AI agents driving
[klayout-tools](https://github.com/2AMLogic/klayout-tools) and the
open-source xschem + ngspice flow.

**Status: spec proposed, bitcell characterized at schematic level.** The
target spec is written but not ratified; the 6T bitcell is drawn as a
schematic and simulated over the 45 PVT corners. No layout, array or
periphery exists yet.

**Built agent-native.** Every specification, decision record, testbench, and
line of documentation here is produced by AI agents working from a ratified
spec and an append-only evidence trail — not human-authored work that agents
merely assisted with. Verification is the product: every claim traces to a
recorded result under PVT corners. Where the agents hit friction with the
open-source tooling — most often
[klayout-tools](https://github.com/2AMLogic/klayout-tools) — that friction is
filed as a public issue against the tool itself, so the fix benefits everyone
using SG13G2, not just this repo.

## Why this block, on this PDK

This is a **port, not a new design**. It follows
[gf180-sram](https://github.com/2AMLogic/gf180-sram), which ratified a fixed
1 kB (256 × 32) single-port macro on a custom-drawn 6T bitcell, carried it
through DRC, LVS and 27-corner PVT margin signoff, and generated its own LEF
abstract. That repo is master for the spec structure, the margin
definitions, the statistical treatment and the harness. The experimental
design is the one every fleet port uses: **the PDK is the variable, not the
design.** Anything that breaks here should be assumed to be the PDK, the
deck or the tools before it is assumed to be the macro.

What changes is the PDK underneath:

- **Supply.** SG13G2's core devices run at 1.2 V, against `gf180-sram`'s
  3.3 V. Margins, corners and timing are re-derived for that rail.
- **A foundry reference at the same size.** SG13G2 ships its own SRAM macro
  library (`sg13g2_sram`), single- and dual-port, including a 1-port
  256 × 32 instance — the same organization as the origin's target. It is
  the comparison point for area and timing here, not something this repo
  wraps.
- **The bitcell question reopens.** The origin found gf180mcu's bitcell only
  embedded inside fixed foundry macros and drew its own. Whether SG13G2's
  is usable standalone is the first question, answered before the spec.
- **The deck.** klt's SG13G2 DRC/LVS deck is newer than its gf180mcu one;
  a dense memory array is a new kind of workload for it.

Free SRAM generators exist for other open PDKs; where one is a useful
reference, use it and say so. Do not reimplement it.

## Target specification

The target specification is proposed in [`spec/sram.md`](spec/sram.md), with
the porting plan ([`spec/porting-plan.md`](spec/porting-plan.md)) and the
decision records beside it. It is **not yet ratified**; ratification is an
operator step. The proposal, copied from the table in `spec/sram.md` (a check in `npm test`
fails if the two diverge; `spec/sram.md` is the source):

| Parameter | Target | Stretch | Origin |
|---|---|---|---|
| Organization | 1 kB, 256 words × 32 bits, fixed instance | parameterized generator | inherited |
| Ports | 1RW, synchronous | 1RW1R | inherited |
| Bitcell | custom-drawn 6T on `sg13_lv_nmos` / `sg13_lv_pmos`, 130 nm | — | re-derived |
| Supply | 1.2 V ±10%: 1.08 / 1.20 / 1.32 V | — | re-derived |
| Views | GDS, LEF, Liberty, generated by this repo's own flow | CDL, Verilog | inherited |
| Margins | read SNM, hold SNM, write margin strictly positive at every corner, plus Monte Carlo | — | inherited |
| Corners | 45 (below) | — | re-derived |
| Signoff | DRC and LVS clean on the full array; every corner recorded | — | inherited |

Maturity ladder: bitcell question answered → porting plan recorded → spec
ratified → bitcell characterized → array assembled → DRC/LVS-clean →
abstract and Liberty views generated and checked → shuttle seat → measured
silicon. **Current position: spec proposed, awaiting ratification** (bitcell question
answered, porting plan recorded).

## Reproducing the results

Every committed record is regenerated by a script in this repo. Detail lives in
[`sim/README.md`](sim/README.md) and [`sim/bitcell/README.md`](sim/bitcell/README.md).
Records are append-only: each run writes a new `records/<UTC>/` directory.

1. **PDK fetch and OSDI build** (Linux x86_64; PDK pinned in `sim/pdk.json`,
   follow the "Cold start" steps 1-2 in `sim/README.md`). **ngspice >= 43 is
   required**: OpenVAF-Reloaded emits OSDI v0.4, which ngspice 42 cannot load.
2. **PDK smoke** (`sim/pdk-smoke/records/*`): `sim/pdk-smoke/run_smoke.sh`.
3. **Bitcell hold/read SNM and write margin, 45 corners**
   (`sim/bitcell/records/*`): `sim/bitcell/run_bitcell.sh`. Every run goes to the
   batch fleet backend (`klt sim --backend batch`), so it needs the fleet, not
   just a local ngspice. Its PDK-free unit test:
   `python3 sim/bitcell/test_bitcell_post.py`.
4. **Signoff record** (`manifests/sg13g2-sram.signoff.json`), regenerated with
   the pinned klt (see `manifests/README.md`):

   ```bash
   uvx --from "klayout-tools==0.8.0" klt signoff --manifest manifests/sg13g2-sram.json \
     --tiers-doc manifests/design-evidence-tiers.md --format json > manifests/sg13g2-sram.signoff.json
   ```

5. **Repo hygiene attestation** (`attest/item10.envelope.json`):
   `npm test` runs the PDK-free checks; the envelope is re-checked with

   ```bash
   uvx --from "klayout-tools==0.8.0" klt signoff --attest 10 \
     --inventory attest/item10.json --check attest/item10.envelope.json
   ```
