# Porting plan: `gf180-sram` to SG13G2

**Status**: Proposed, 2026-10-17 (not self-ratified)
**Origin read**: `2AMLogic/gf180-sram` @ `d0bacc0fceb6e9400e54e3efe15ec1630711faa9`
(local checkout `~/GitHub/gf180-sram`, `main` HEAD on 2026-10-17)

`gf180-sram` is master for the spec structure, margin definitions,
statistical treatment and harness. This table lists every item as
**inherited** (taken unchanged, with the origin file) or **re-derived**
(device-level, with the reason). Departures from the origin are decision
records in this directory.

## Re-derived

| Item | Why it cannot be inherited | Where |
|---|---|---|
| Bitcell: topology and sizing | Different devices (`sg13_lv_nmos` / `sg13_lv_pmos`, 130 nm, 1.2 V) and a different answer to the first question | `spec/bitcell-decision.md` |
| Supply: 1.2 V ±10% (1.08 / 1.20 / 1.32 V) | Origin is 3.3 V; SG13G2 core devices are 1.2 V | `spec/sram.md` |
| Rail sharing (array vs periphery) | Shipped macros separate `VDD` from `VDDARRAY`; the origin has one rail | `spec/sram.md`, open |
| PVT corners: `mos_tt/ss/ff/sf/fs` × −40/25/125 °C × 3 supplies = 45 | Origin used `ff/tt/ss` only (27). SG13G2 ships skew corners | `spec/sram.md` |
| Write-pulse width value | Origin's 2 ns was a testbench window tied to a 180 nm, 3.3 V cell; the number does not transfer | `spec/write-pulse-width-decision.md` |
| Reference row (area, timing) | Different comparison part (`RM_IHPSG13_1P_256x32_c2_bm_bist`) | `spec/sram.md` |
| Deck acceptance | Different deck (klt SG13G2, newer) | `spec/sram.md` |
| PDK pin and OSDI model loading | Origin pinned `gf180mcuD`; SG13G2 compact models load through OSDI | #5, not this issue |
